# 안내산악회 · 산악회 방 - 설계와 시험 (2026-10-22)

운영 서버는 `club.enabled` · `party.enabled` 둘 다 꺼 둔 채로, 이 문서의 시험을 PC 에서 마친 뒤 홍TV님이 켭니다.

## 1. 역할 나누기

| 단계 | 누가 | 어디서 |
|---|---|---|
| 모집 · 예약 · 결제 · 환불 | 산악회 | 산악회 누리집 · 다음 카페(그대로) |
| 일정 알리기 · 손님 이어 주기 | routefly | 산 페이지 "🚌 ○○산 가는 안내산악회" · 일정 모음(clubs.html) → "예약 ›" 으로 산악회 화면 |
| 산행 날(탑승 · 위치 · SOS · 하산) | routefly 산악회 방 | party.html (손님은 링크 + 별명, 가입 · 앱 없음) |

손님은 routefly 에 가입하지 않습니다. 산악회 운영자도 아이디 · 비밀번호가 없습니다.

## 2. 산악회가 들어오는 길 - 관리 링크 (홍TV님 결정)

1. 산악회가 club.html 에서 **등록 신청**: 산악회 이름 · 운영자 연락처(공개 안 함) · 손님 문의 번호(선택, 공개) · 누리집 주소.
2. 홍TV님(운영자 기기 = /stats 를 연 브라우저)이 club.html 아래 운영자 칸에서 확인:
   누리집 · 연락처로 **전화해 실제 산악회인지** 본 뒤 "✅ 확인".
3. "🔗 관리 링크" → 링크가 한 번만 보임 → 그 연락처로 문자 · 카톡.
4. 산악회가 링크를 열면 그 기기에 30일 로그인. 링크를 잃으면 새 링크(옛 링크 · 로그인은 끊김).

- 확인 안 된 신청은 14일 뒤, 1년 동안 안 쓴 산악회는 그 뒤 저절로 지움. "그만두기" 는 바로 지움.
- 누리집 주소를 바꾸면 다시 확인(그동안 일정 안 보임) - 확인 뒤 낚시 주소로 바꾸기 막기.
- 일정의 예약 주소는 누리집과 **같은 곳(호스트)** 만 받음.

## 3. 일정 올리기

- 하나씩: 날짜 · 시각(한국 시각) · 산(100대 명산 목록 또는 "기타") · 제목 · 탑승지(비우면 기본값) · 회비 · 예약 주소 · **같은 요일 반복(최대 12주)**.
- **📄 복사**: 일주일 뒤 같은 산행으로 채움.
- **📋 여러 일정 붙여넣기**: 한 줄에 `10/25 07:00 가야산 만물상 당일 39000` - 미리 보기 뒤 올리기.
- 산악회마다 300개, 지난 일정은 출발 하루 뒤 지움.
- **🧭 산악회 방**: 그 일정 · 기본 차량 수 · 좌석으로 방 만들기 칸을 채움(인솔자 이름은 비움). 산악회는 하루 40방까지.

## 4. 손님이 보는 것

- 산 페이지 아래(일정이 있을 때만) · 일정 모음: 날짜순, **광고는 2~3개만 맨 위**에 "광고" 표시, 링크는 rel="sponsored".
- "예약 › 반더룽.com" 처럼 어디로 가는지 함께 보임. 출발 뒤 2시간까지는 "출발함" 으로.
- "routefly 는 예약을 받지 않고 산악회가 있는지만 전화로 확인 - 안전 · 보험 · 환불은 산악회 책임" 문구.

## 5. 산행 날 - 산악회 방에 더한 것

- **📋 예약 명단 붙여넣기**: `21 홍길동 사당` · `홍길동 / 21번 / 사당`(카페 댓글) · `2-21 홍길동`. 전화번호는 저절로 빠짐.
- **폰 없는 예약자**: 좌석표에서 이름을 누르고 인솔자가 ✅ 출발 탑승 · 🚌 하산 탑승 체크. 출발 때 체크 안 된 예약자는 취소 표시. 인원 · "아직 하산 안 함" 에도 들어감.
  그 자리로 폰 참가하면 체크를 이어 받음.
- **폰 회원도 인솔자가 하산 탑승 체크**(폰을 못 누른 분).
- **🧭 인솔자 넘기기 · 함께 인솔**: 한 번 쓰는 인솔자 코드 → 그분이 들어오면 처음 폰은 "방 나가기" 가능.

## 6. 보안 점검에서 고친 것

- 비밀번호를 없애 비밀번호 확인으로 서버를 바쁘게 하는 공격 · 계정 잠그기 · 아이디 알아내기가 없어짐.
- 신청: 한 곳 하루 5번 · 서버 전체 하루 30번, 먼저 셈(동시에 보내 넘기기 막기). 확인 대기 100곳까지.
- 로그인 쿠키는 산악회마다 10개까지, 서버엔 해시만. 관리 링크 틀림은 15분 10번.
- 파일을 읽다 실패하면 저장을 멈춤(빈 것으로 덮어쓰지 않음) - 운영자 칸에 알림. 쓰기 실패는 다시 시도.
- 숫자 칸에 글자를 넣어도 내부 오류 글이 나가지 않음.
